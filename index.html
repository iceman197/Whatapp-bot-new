06 / HELP CENTER

Questions & answers

Read this before requesting a pairing code.

Why does the dashboard say “Checking”?

The browser must reach a running backend. If the website is hosted as a static page only, the API actions cannot work. Deploy the Node.js web service and use its service URL.

Where do I get the admin token?

You create a long random token in Render Environment settings as ADMIN_TOKEN. The same token is typed into this dashboard. Never paste it into public messages or commit it to GitHub.

Why can a pairing code fail?

The phone number must match the configured owner number, the backend must be running, and the WhatsApp connection must be able to initialize. If it fails, inspect Render logs without sharing secrets or session data.

Will my session survive a restart?

It needs persistent storage. The included Render configuration requests a persistent disk at /var/data. Confirm the disk is attached and DATA_DIR points there.

Is Baileys the official WhatsApp Business API?

No. Baileys is a community library that connects through WhatsApp Web. The official WhatsApp Business Platform is a different product with Cloud API credentials and webhooks.

Is the project already deployed?

No. The ZIP contains project files and deployment instructions. Installing dependencies, live pairing, Gemini requests, and Render deployment must still be tested in your account.

08 / OPERATIONS HANDBOOK

Deployment and maintenance notes

Practical reminders for the person maintaining this service.

Reference
Environment variablesADMIN_TOKEN is required. OWNER_NUMBER identifies the only permitted pairing number. PORT is assigned by the host. DATA_DIR must point to persistent storage in production.
First deploymentInstall the supported Node.js runtime, allow the package manager to install dependencies, start the service with npm start, then inspect the health endpoint.
Session dataBaileys authentication state contains sensitive login material. Do not publish it, attach it to support messages, or put it in the Git repository.
Updating codeMake a backup of private persistent data before planned changes. Test a change in a safe environment before using it with your personal WhatsApp account.
API failuresCheck the service status, environment configuration, outbound connectivity, and provider status. Logs should describe the error without printing tokens or pairing codes.
Privacy by designDo not collect more message content than required. Restrict dashboard access and rotate any credential that may have been exposed.
What does a successful health check prove?

It proves only that the HTTP health endpoint answered. It does not prove that WhatsApp is paired, messages can be sent, Gemini credentials are valid, or the service will remain available.

What should I include when reporting a bug?

Share the non-sensitive error message, the action you took, and the approximate time. Never share your admin token, pairing code, API key, WhatsApp auth files, private phone messages, or complete environment settings.

Can I use this page before deploying the backend?

You can view the dashboard locally, but all administrative controls need the matching backend API. A static GitHub Pages website alone cannot create or maintain a Baileys WhatsApp connection.

Why is the owner phone number checked twice?

The dashboard asks for a number, but the server independently compares it with OWNER_NUMBER. Browser validation is for convenience, not security; authorization must happen on the server.

Does private mode block all commands?

In this starter version, private mode blocks non-owner AI replies and plain-text AI processing. Public basic commands such as .help and .ping remain available. Review and test behavior before expanding it.

Why is the entire planned command catalogue not shown as implemented?

Displaying a command in a user interface does not implement it. This dashboard lists only the starter commands currently present in the backend. Future commands should be built, authorized, and tested individually.

09 / FIELD GUIDE

Reference cards

Operational notes to help you troubleshoot without exposing private data.

Pairing preparationConfirm that the owner number is correct, international, and configured on the backend. Pairing codes are temporary and should be entered only in the WhatsApp app on the phone you control.
Pairing troubleshootingIf no code appears, check the backend is awake, the admin token is correct, the number matches OWNER_NUMBER, and the session directory is writable. Do not retry repeatedly if WhatsApp reports a temporary restriction.
Backend authorizationThe dashboard sends an Authorization bearer token to administrative routes. The server compares the token and checks owner phone numbers independently. Never rely on hiding buttons in HTML as authorization.
Secret rotationIf a token or API key was pasted into a public location, replace it at the provider or hosting environment. Remove it from source files and history where possible; deleting a visible line alone may not remove repository history.
Persistent storageWhatsApp credentials and settings are stored under DATA_DIR. In a hosted deployment, the directory should be mounted on persistent storage. Check the exact mount path in the host dashboard.
AI model configurationThe selected model name is sent to the server and used for Gemini requests. A model name alone does not provide access: a valid API key, account access, network connectivity, and provider availability are also needed.
Command expansionImplement each command in the backend command router, decide whether it is public or owner-only, validate its arguments, and test both authorized and unauthorized senders.
Safe message handlingTreat all incoming message text as untrusted input. Limit the size of inputs, handle malformed messages, catch provider errors, and avoid logging full private conversations.
Public and private modesChoose the intended access behavior before changing modes. A private-mode policy should be enforced in the backend for every relevant command, not merely in the dashboard.
Deployment healthA running HTTP server does not guarantee an active WhatsApp session. Monitor health separately from connection state and test message sending with a small, consent-based test.
Repository hygieneKeep package manifests and source code in Git. Exclude dependency folders, logs, environment files, session credentials, generated private settings, and local data.
Recovering a sessionIf a connection closes, check the sanitized service logs and the saved session state. Avoid deleting authentication files casually; removing them may require linking the account again.
Owner identityUse a stable owner number in international digits-only form. Do not accept a sender-supplied owner field or a phone number posted in a command as proof of ownership.
HTTP errors401 usually indicates missing or incorrect admin authorization; 403 indicates a restricted operation; 429 indicates the request limit; 5xx indicates a server-side issue. Read the safe error response before retrying.
Version updatesDependencies and WhatsApp Web behavior can change. Review release notes, update in a controlled manner, and verify pairing, receiving messages, commands, and reconnect behavior after updates.
Testing disciplineSeparate syntax checks, local health checks, authenticated endpoint tests, provider API tests, real WhatsApp linking, and deployment verification. Passing one test does not imply all others passed.
Mobile dashboardThe layout adapts to small screens. Use a private device, avoid shared browsers, and clear any pasted secrets from input fields after use.
API key storageThis starter stores the configured Gemini key on the backend in the data directory. Keep that directory private and persistent. Do not expose the key through a GET endpoint or client-side script.
Owner command checksNormalize the sender's number on the backend before comparing it with OWNER_NUMBER. Test number formatting variants and verify that non-owner senders cannot change settings.
Support informationWhen asking for help, provide only sanitized logs and describe what you expected versus what happened. Replace phone numbers and redact all credentials in screenshots.
